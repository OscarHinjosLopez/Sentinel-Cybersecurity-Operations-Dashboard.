# Technical decisions

These decisions describe the implemented portfolio architecture, rather than a production backend design.

| Decision                   | Rationale and tradeoff                                                                                                                                                                                                                        |
| -------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Signals rather than NgRx   | Feature stores and computed state fit the current domain scope without an additional store framework. RxJS remains responsible for async/event composition. A larger team or cross-domain workflow could justify stronger global conventions. |
| Repository abstractions    | Stores consume typed contracts, keeping mock generation/mutations separate from UI and allowing future API adapters. The interfaces do not themselves supply backend persistence.                                                             |
| Mock backend               | A self-contained personal frontend project can demonstrate investigations, permissions and events without infrastructure or real incident data. Auth, authorization and persistence remain demonstrably limited.                              |
| ECharts                    | The existing dashboard needs line, pie and bar visualizations. Modular imports and SVG rendering keep registration explicit; the remaining chart engine is sizeable, so it is deferred.                                                       |
| Zoneless Angular           | Angular 22's default zoneless setup fits Signals and modern standalone components. Tests exercise asynchronous rendering without introducing Zone.js.                                                                                         |
| URL-driven table queries   | Filters, sorting and pagination survive reload and browser history and can be linked directly. Parsers must validate unknown/invalid query values and normalize page bounds.                                                                  |
| Modular realtime transport | Validation, deduplication, projections and reconnect behavior can be tested independently of a socket. The simulator lacks durable replay and a production authentication handshake.                                                          |
| Client-only deployment     | There is no SSR requirement for an authenticated mock SOC demo. A static server with SPA fallback is sufficient; hosting configuration must preserve assets and deep links.                                                                   |
| Vercel plus Docker         | Vercel provides the portfolio publishing path; nginx offers a portable container. Both serve the same production artifacts. No token-based deploy workflow is added.                                                                          |
| CI gates, local Lighthouse | Formatting, types, coverage, browser flows, bundles and container smoke can fail CI reliably. Lighthouse measurements remain local laboratory evidence rather than a noisy performance gate or field data.                                    |
